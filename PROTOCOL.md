# PixMob Wave2 RF protocol notes

This document describes the RF signal generated by this repository. It targets
the European PixMob Wave2 / Waveband 2 hardware that responds at 868.415 MHz.

## Radio layer

| Parameter | Value |
|---|---|
| Carrier | 868.415 MHz |
| Modulation | OOK / ASK |
| Bit-cell duration | 500 µs |
| Inter-frame low gap | 9 bit cells (4.5 ms) |
| Flipper preset | `FuriHalSubGhzPresetOok650Async` |

The Flipper representation uses signed RAW durations in microseconds. Positive
durations switch the OOK carrier on; negative durations switch it off.

## Frame layout

A frame contains 90 bits:

```text
┌────────────────────┬───────────────┬───────────────────────────────┐
│ Preamble + sync    │ CRC A         │ 7 line-coded fields + CRC B   │
│ 18 bits            │ 8 bits        │ 64 bits                       │
└────────────────────┴───────────────┴───────────────────────────────┘
```

The 18-bit prefix is:

```text
10101010 10101010 01
```

The remaining nine bytes are transmitted most-significant bit first:

```text
CRC-low, mode, green, red, blue, attack/random, release/hold, group, CRC-high
```

Every decoded field is six bits. Before transmission, each field is replaced by
an eight-bit symbol from the PixMob 6b/8b table. This limits long runs of equal
bits so the receiver can maintain timing synchronization.

## Persistent color command

The files in this repository use:

| Field | Value |
|---|---|
| Mode | `0x11` (persistent receiver color) |
| Green | `green >> 2` |
| Red | `red >> 2` |
| Blue | `blue >> 2` |
| Attack/random | `0` |
| Release/hold | `7` |
| Group | `0` (universal) |

Because channels are reduced from eight bits to six, RGB values are represented
in steps of four.

OFF is simply the persistent command with all three channels set to zero.

## CRC-12

The checksum is calculated over the seven **line-coded** body bytes—not the
decoded six-bit values.

| Parameter | Value |
|---|---|
| Initial register | `0xC69` |
| Reversed polynomial | `0x8F3` |
| Width | 12 bits |
| Input order | Bytes in frame order, bits MSB-first |

The lower six checksum bits are line-coded into the first payload byte. The
upper six bits are line-coded into the ninth payload byte.

## Known vectors

### Wake

Decoded body:

```text
00 00 00 00 08 0F 00
```

Encoded frame:

```text
56 84 84 84 84 62 36 84 29
```

### Persistent red, group 0

Decoded body:

```text
11 00 3F 00 00 07 00
```

Encoded frame:

```text
51 4D 84 A6 84 84 24 84 4C
```

### Persistent OFF, group 0

Decoded body:

```text
11 00 00 00 00 07 00
```

Encoded frame:

```text
66 4D 84 84 84 84 24 84 85
```

These vectors are enforced by the automated test suite.

## Wake behavior

The wristband aggressively sleeps to preserve its batteries. The `one_press`
files send 336 valid black wake frames before the selected action. At the timing
above, the complete wake portion lasts approximately 16.6 seconds.

The `quick_after_wake` files contain only 20 action frames and complete in about
one second. They require the receiver to already be awake.
